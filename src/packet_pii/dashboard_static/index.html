    FROM CAPTURE TO EVIDENCE

    How TRACE works

    SIMPLE VIEW

    Follow the data, inspect the finding.

    1. Choose a capture and a detection mode. Rules are selected by default; contextual AI requires a loaded checkpoint and your selection.
    2. TRACE reads captured packets, groups TCP traffic and reconstructs available plaintext HTTP messages.
    3. It extracts HTTP text fields and checks them for potential personal data. Optional BiLSTM inference adds contextual identity predictions.
    4. Review masked findings and their network evidence. Missing findings do not prove a capture is safe.
    TECHNICAL VIEW

    Scope and limits are part of the result.

    PCAP and PCAPNG input → TCP stream reconstruction → HTTP/1.x parsing → field extraction → deterministic rules and optional BiLSTM → masked findings and JSON report.

    Rules recognise structured patterns and sensitive field names. Contextual inference reports predicted identity spans with raw, uncalibrated scores. The inspector shows field location, HTTP message, endpoints and detector; it does not explain the model’s internal reasoning.

    TRACE does not decrypt TLS. Unsupported protocols, capture truncation, stream gaps, processing limits and incomplete model inference can hide evidence. Review report limitations and integrity indicators. Findings are candidates, not proof of identity, misuse or exfiltration.
