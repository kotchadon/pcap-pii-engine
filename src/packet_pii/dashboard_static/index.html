                        Getting started

                        1. Choose a capture. Drop a .pcap or .pcapng file on New analysis, or try the sample. Analysis starts straight away and can be cancelled.
                        2. Read the summary. It says how many potential findings there are, what kinds of information they involve and whether the analysis was complete.
                        3. Inspect a finding. Select it in Findings. The inspector opens beside the list and shows where it appeared, why TRACE flagged it and the evidence. Use ↑ and ↓ to move between findings.
                        4. Follow the evidence. Open the HTTP message to see the request, the response, the fields and the packets behind it. Back returns you to the finding.
                        5. Export. Export report downloads the findings, including visible personal details. Passwords and tokens stay protected in the report; keep exports private.

                        Limits to keep in mind

                        • Encrypted traffic is not read. TRACE does not decrypt HTTPS (TLS), so its contents are not inspected.
                        • No finding does not mean no personal data. Unsupported protocols, gaps in the capture and processing limits can hide evidence. The summary says when this happened.
                        • Findings are candidates. A finding does not prove identity, misuse or exfiltration.
                        • Scores are not accuracy. Rule scores are heuristics. Model scores are uncalibrated.
                        • Evidence points to bytes, not guesses. Packet ranges support a whole field or message. TRACE never invents the exact byte position of a detected value.

                        Terms used in TRACE

                        Packet
                        One frame recorded in the capture file. A single web request can span many packets.
                        Connection
                        All TCP traffic between two endpoints, for example 10.0.0.5:51344 and 93.184.216.34:80.
                        Conversation
                        An HTTP request and the responses observed for it, such as POST /login answered by HTTP/1.1 200.
                        Field
                        A value TRACE extracted from a message: a header, query parameter, form value, JSON value or text body.
                        Finding
                        A field, or part of one, that looks like personal information, such as an email address in a form field.
                        Rules and model
                        Rules match known formats and field names. The optional contextual model suggests names and usernames from surrounding text.
                        Original values
                        Names, emails, phone numbers and other non-credential findings appear as detected. Passwords and tokens can be inspected using the original recording when available.
                        Incomplete analysis
                        Some packets were missing or a processing limit was reached, so part of the traffic could not be fully read.

                        How the analysis runs

                        PCAP and PCAPNG input → TCP stream reconstruction → HTTP/1.x and supported HTTP/2 parsing → field extraction → deterministic rules and optional BiLSTM → findings with original non-credential values and an exportable JSON report.

                        The inspector shows field location, HTTP message, endpoints and detector. It does not explain the model’s internal reasoning. Review the completeness note and limitations in the summary before relying on a result.
