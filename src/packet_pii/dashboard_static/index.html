    What is a network recording?

    A file that records network activity, usually made with a tool such as Wireshark or tcpdump. These files end in .pcap or .pcapng. TRACE reads the unencrypted web conversations inside; encrypted (HTTPS) content stays unreadable.

                        1. Choose a recording

                          A network recording (.pcap or .pcapng) captures what devices sent over a network. Choose one, or try the fictional sample. It never leaves this computer.

                        2. TRACE rebuilds the web conversations

                          It puts the recorded pieces back together into the requests devices sent and the replies they received. Encrypted (HTTPS) conversations stay unreadable.

                        3. It looks for possible personal details

                          Pattern checks recognise things like email addresses, phone numbers and card numbers, plus form fields labelled “name” or “password”. An optional AI can suggest names and usernames.

                        4. You inspect the original context

                          Select any finding to see the value, where it appeared, why TRACE noticed it and the web conversation it came from. Use ↑ and ↓ to move between findings.

                        A finding is something to review, not a verdict. TRACE shows what appeared in the readable parts of a recording; it can’t see encrypted content or activity that wasn’t recorded.

                        For technical investigators

                        Show

                        Limits

                        • Encrypted traffic is not read. TRACE does not decrypt HTTPS (TLS), so its contents are not inspected.
                        • No finding does not mean no personal data. Unsupported protocols, gaps in the capture and processing limits can hide evidence. The summary says when this happened.
                        • Findings are candidates. A finding does not prove identity, misuse or exfiltration.
                        • Scores are not accuracy. Rule scores are heuristics. Model scores are uncalibrated.
                        • Evidence points to bytes, not guesses. Packet ranges support a whole field or message. TRACE never invents the exact byte position of a detected value.

                        Terms

                        Packet
                        One frame recorded in the capture file. A single web request can span many packets.
                        Connection
                        All TCP traffic between two endpoints, for example 10.0.0.5:51344 and 93.184.216.34:80.
                        Conversation
                        An HTTP request and the responses observed for it, such as POST /login answered by HTTP/1.1 200.
                        Field
                        A value TRACE extracted from a message: a header, query parameter, form value, JSON value or text body.
                        Original values
                        Names, emails, phone numbers and other non-credential findings appear as detected. Passwords and tokens stay protected and can be checked against the original recording when it was kept.
                        Incomplete analysis
                        Some packets were missing or a processing limit was reached, so part of the traffic could not be fully read.

                        Pipeline

                        PCAP and PCAPNG input → TCP stream reconstruction → HTTP/1.x and supported HTTP/2 parsing → field extraction → deterministic rules and optional BiLSTM → findings with original non-credential values and an exportable JSON report.

                        The inspector shows field location, HTTP message, endpoints and detector. It does not explain the model’s internal reasoning.
